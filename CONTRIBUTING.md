# Contributing

Спасибо за вклад в Work Activity Monitor. Это приложение обрабатывает чувствительные
данные, поэтому изменения должны сохранять прозрачность сбора, согласие пользователя и
строгие границы доступа.

## Подготовка окружения

Нужны Python 3.12+, Node.js 22+, npm и GNU Make. Для Windows-клиента дополнительно нужны
Visual Studio Build Tools с C++ workload или MinGW-w64.

```bash
make setup
make check
```

Подробная настройка: [`docs/DEVELOPMENT.md`](./docs/DEVELOPMENT.md).

## Процесс изменения

1. Создайте отдельную ветку с небольшим, сфокусированным изменением.
2. Не добавляйте реальные секреты, сертификаты, базы данных или скриншоты.
3. Добавьте regression-тест для исправления и тесты новых бизнес-правил.
4. Обновите документацию, если меняется API, конфигурация, архитектура или модель угроз.
5. Запустите `make check`; C++-изменения дополнительно соберите как `Release | x64`.
6. В pull request опишите влияние на приватность и безопасность.

## Требования к коду

- Python должен проходить Ruff, Bandit и `unittest`.
- Frontend должен проходить статическую security-проверку, unit-тесты и сборку.
- SQL-схема изменяется только новой миграцией.
- API должен сохранять единый JSON-формат ошибок.
- Новые зависимости требуют объяснения и должны проходить аудит уязвимостей.

Об уязвимостях сообщайте приватно по инструкции в [`SECURITY.md`](./SECURITY.md), а не в
публичном issue.
